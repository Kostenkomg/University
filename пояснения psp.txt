ПОСТРОЧНОЕ ПОЯСНЕНИЕ КОДА И ОТВЕТОВ ФАЙЛА psp.py

1. Импорт и структура файла
- Строка 1: from car import Car, MonsterTruck — импортирует классы Car и MonsterTruck из соседнего файла car.py для работы с ними в тестах.
- Строка 3: def _q_01(): — объявляет функцию-заглушку, внутри строки документации (docstring) которой записаны интерактивные тесты (doctest) для проверки понимания работы классов.
- Строка 107: return 0 — возвращает 0 при вызове функции _q_01() (сама логика проверки находится в документационной строке выше).
- Строки 111–120: if __name__ == '__main__': ... — служебный блок автопроверки. Он находит функцию _q_01, снимает флаг пропуска тестов (# doctest: +SKIP) и пошагово сверяет реальный вывод Python с вписанными ответами до первой ошибки (FAIL_FAST).

2. Построчное пояснение ответов (Часть 1: атрибуты экземпляра и метод paint)
- Строки 8–10: apalkoff_car = Car('Tesla', 'Model S') и apalkoff_car.color -> 'Без цвета. Покрась меня.' — при создании объекта конструктор __init__ записывает это стартовое значение в атрибут self.color.
- Строки 12–13: apalkoff_car.paint('чёрный') -> 'Цвет Tesla Model S теперь чёрный' — метод paint обновляет self.color и возвращает строку отчёта о покраске.
- Строки 15–16: apalkoff_car.color -> 'чёрный' — повторное обращение к атрибуту показывает уже новое значение.

3. Построчное пояснение ответов (Часть 2: бензин экземпляра и класса)
- Строки 21–23: apalkoff_car = Car('Tesla', 'Model S') и apalkoff_car.model -> 'Model S' — возвращает модель, сохранённую при создании нового объекта.
- Строки 25–27: apalkoff_car.gas = 10 и apalkoff_car.drive() -> 'Tesla Model S делает врум-врум!' — запаса бензина хватает (10 > 0), метод уменьшает self.gas на 10 (остаётся 0) и возвращает звук мотора.
- Строки 29–30: apalkoff_car.drive() -> 'Tesla Model S не может ехать!' — так как self.gas равен 0, срабатывает условие self.gas <= 0.
- Строки 32–33: apalkoff_car.fill_gas() -> 'Количество бензина в Tesla Model S: 20' — метод прибавляет 20 к текущему нулевому запасу и возвращает строку с новым объёмом.
- Строки 35–36: apalkoff_car.gas -> 20 — проверяет текущий запас топлива в конкретном экземпляре машины.
- Строки 38–39: Car.gas -> 30 — атрибут самого класса Car не изменялся и остался равен исходному значению 30.

4. Построчное пояснение ответов (Часть 3: поиск атрибутов в классе и объекте)
- Строки 44–45: Car.headlights -> 2 — обращение к атрибуту класса Car напрямую.
- Строки 47–48: apalkoff_car.headlights -> 2 — у экземпляра своего атрибута headlights нет, поэтому Python находит его в родительском классе Car.
- Строки 50–52: Car.headlights = 3 и apalkoff_car.headlights -> 3 — после изменения атрибута в классе Car экземпляр по-прежнему берёт значение из класса и видит новое число 3.
- Строки 54–56: apalkoff_car.headlights = 2 и Car.headlights -> 3 — присваивание через экземпляр создаёт локальный атрибут только внутри apalkoff_car, не меняя общий атрибут класса Car.

5. Построчное пояснение ответов (Часть 4: вызов методов через объект и через класс)
- Строки 61–63: apalkoff_car.wheels = 2 и apalkoff_car.wheels -> 2 — создаёт и читает локальный атрибут wheels у конкретного экземпляра.
- Строки 65–66: Car.num_wheels -> 4 — стандартное количество колёс в классе Car остаётся равным 4.
- Строки 68–69: apalkoff_car.drive() -> 'Tesla Model S не может ехать!' — так как у машины 2 колеса при норме 4 (self.wheels < Car.num_wheels), поездка невозможна.
- Строки 71–72: Car.drive() -> TypeError — при вызове метода напрямую от имени класса Car параметр self не передаётся автоматически, возникает ошибка нехватки аргумента.
- Строки 74–75: Car.drive(apalkoff_car) -> 'Tesla Model S не может ехать!' — здесь экземпляр apalkoff_car передан первым аргументом (вместо self) вручную, поэтому метод отрабатывает штатно.

6. Построчное пояснение ответов (Часть 5: наследование в MonsterTruck)
- Строки 80–83: apalkoff_car = MonsterTruck('Монстр', 'Бэтмобиль') и apalkoff_car.drive() -> сначала выводит в консоль 'ДРЫН-ДЫН-ДЫН! Этот монстр-трак просто огромный!' (вызов self.rev()), а затем возвращает 'Монстр Бэтмобиль делает врум-врум!' (вызов родительского Car.drive(self)).
- Строки 85–86: Car.drive(apalkoff_car) -> 'Монстр Бэтмобиль делает врум-врум!' — вызывает метод drive напрямую из базового класса Car, минуя переопределённый метод MonsterTruck (поэтому рычания rev() нет).
- Строки 88–90: MonsterTruck.drive(apalkoff_car) -> печатает 'ДРЫН-ДЫН-ДЫН! Этот монстр-трак просто огромный!' и возвращает 'Монстр Бэтмобиль делает врум-врум!' — вызывает переопределённый метод класса MonsterTruck с ручной передачей объекта.
- Строки 92–93: Car.rev(apalkoff_car) -> AttributeError — метод rev определён только в дочернем классе MonsterTruck, а в базовом классе Car такого атрибута не существует.
